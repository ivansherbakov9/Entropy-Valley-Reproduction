# Воспроизведение Entropy-Valley для диффузионного машинного перевода

**Статья:** [Length-Adaptive Decoding for Masked Diffusion Machine Translation (Yan Zhan et al., EMNLP 2026)](https://aclanthology.org/2026.emnlp-main.623/)

## Идея

В отличие от авторегрессионных языковых моделей, которые генерируют текст последовательно до токена EOS, masked diffusion language models (MDLM) обычно получают заранее заданное количество замаскированных позиций и постепенно восстанавливают токены.

Для машинного перевода это создаёт проблему: длину перевода приходится выбирать ещё до начала генерации. Если выбрать слишком маленькую длину, модель может пропустить часть исходного текста, если слишком большую - добавить лишнее.

Авторы предлагают **Entropy-Valley (EV)** - метод выбора длины без дополнительного обучения. Для нескольких возможных длин модель делает forward pass с полностью замаскированным переводом. Затем вычисляется средняя энтропия распределений предсказанных токенов:

$$
H(L)=-\frac{1}{L-1}\sum_{i=1}^{L-1}\sum_{v\in V}p_i(v)\log p_i(v)
$$

Выбирается длина с минимальной средней энтропией:

$$
L^*=\arg\min_{L\in\mathcal L}H(L).
$$

Идея в том, что низкая энтропия может указывать на длину, при которой модель наиболее уверена в восстановлении перевода. После выбора длины запускается обычное диффузионное декодирование.

## Наш эксперимент

Воспроизвели эксперимент для направления English -> Chinese (En->Zh) на 400 предложениях из тестового набора WMT22.

Использовали:

- **LLaDA-8B-Base** с официальной LoRA для En-Zh, предоставленной авторами.
- **Entropy-Valley** из официального репозитория статьи.
- **Minimum Entropy Decoding (MED)** с 32 шагами генерации.
- Две NVIDIA T4 на Kaggle, между которыми распределена модель (веса backbone загружены в 4-битной NF4-квантизации)

Сравнили три способа выбора длины:

1. Fixed Ratio: фиксированная длина, рассчитанная из длины исходного предложения с коэффициентом 0.8.
2. Entropy-Valley: выбор лучшей длины из пяти кандидатов с коэффициентами 0.7-0.9 по минимальной энтропии.
3. Oracle Length: длина, рассчитанная по эталонному переводу. Это теоретический ориентир, недоступный при обычном переводе.

Для всех трёх вариантов использовали одну модель и одинаковый алгоритм декодирования. Различался только способ выбора длины.

## Мои Результаты

| Метод | sacreBLEU | chrF | Length MAE | **COMET-22** |
|---|---:|---:|---:|---:|
| Fixed Ratio | 34.797 | 30.671 | 2.652 | 0.846 |
| **Entropy-Valley** | **36.261** | **32.446** | **2.125** | **0.853** |
| Oracle Length | 39.771 | 35.363 | 0.000 | 0.865 |

Таким образом, при неизменной модели и том же декодере выбор длины через энтропию позволил улучшить качество перевода.

## Вывод

На нашей выборке **основной результат статьи воспроизвёлся**: Entropy-Valley улучшил качество перевода относительно фиксированного коэффициента длины, не требуя дополнительного обучения модели.

Интересно, что улучшение получилось только за счёт выбора количества токенов перед генерацией. Мы не меняли архитектуру LLaDA, её веса или алгоритм восстановления токенов.

Полученные результаты согласуются с основной идеей авторов: для masked diffusion language models выбор длины выходной последовательности сам по себе является важной частью процесса генерации.
